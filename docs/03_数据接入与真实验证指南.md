# 数据接入与真实验证指南

## 1. 数据边界

自主命题赛道没有组委会提供的本题专用数据。当前 `data/demo` 为自建可复现增强工程基准，用于回归测试和演示。若要论证真实应用价值，参赛队需在获得授权、完成脱敏并遵守组织安全制度的前提下采集 Agent 与主机遥测；不得从未知来源抓取或提交包含个人信息、凭据、Cookie、密钥和商业秘密的日志。

## 2. 统一字段

| 字段 | 含义与示例来源 |
|---|---|
| timestamp | ISO 8601 时间；来自工具调用时间或主机事件时间 |
| entity_id | 脱敏后的 agent、会话、主机用户或进程树标识 |
| source | agent 或 host |
| event_type | model/tool/memory/permission/process/network/file/registry 等 |
| action | call/read/write/connect/start/set/query 等 |
| object_type | tool/file/domain/process/secret 等 |
| object_name | 脱敏对象名称；长度上限 2048 |
| result | success/failure/blocked |
| label/scenario | 仅离线训练评估使用，线上可缺省 |

事件按 JSONL 保存，每行一个对象。同一数据集必须统一时区；转换器会拒绝无效时间、空必填字段和非法标签。

## 3. 采集与切分建议

优先收集正常业务轨迹，再在隔离沙箱中执行经过审批的安全测试场景。训练、验证和测试应按实体隔离；条件允许时再按时间切分。所有人工增强只进入训练，测试集应包含高风险但合法的困难正常行为，以及训练未见的场景模板。数据元信息记录生成或采集时间、样本数量、切分策略、脱敏方式、随机种子和文件 SHA-256。

## 4. 推荐实验矩阵

1. 异常专属词元查表基线；
2. 透明顺序规则；
3. Transformer 单模型；
4. Transformer 与规则混合链路；
5. 去除下一事件辅助任务的消融；
6. 不同窗口长度与步长；
7. 留一异常场景测试；
8. 跨实体、跨时间或跨环境验证；
9. CPU 延迟、吞吐、内存和完整文件处理时间；
10. 误报、漏报和解释证据的人工复核。

未实际运行的实验只能写为后续计划，不填写推测数字。

## 5. 接入与复测命令

CSV 转换：

```powershell
.\.venv\Scripts\python.exe scripts\convert_csv.py raw.csv data\local\events.jsonl --mapping configs\csv_mapping.example.json
```

若启用匿名化，需额外传入秘密盐；盐只在本地保存。准备好 `train.jsonl`、`validation.jsonl`、`test.jsonl` 后：

```powershell
.\.venv\Scripts\python.exe scripts\train.py --data-dir data\local --output artifacts\local_agentguard.pt
.\.venv\Scripts\python.exe scripts\evaluate.py --checkpoint artifacts\local_agentguard.pt --input data\local\test.jsonl --output-dir artifacts\local_evaluation
```

真实验证结果应与自建工程基准分表，写清数据来源、授权范围、切分方式、硬件环境和限制。

## 6. 可选公共数据

Loghub BGL/HDFS 可用于补充系统日志格式接入验证，其中 BGL_2k 带公开异常标签，适合现场演示“上传原始日志 -> 自动解析 -> 输出告警链路”。CERT Insider Threat、LANL Cyber Security Science Data 和 DARPA OpTC 可用于补充主机行为验证，但不等同于 AI Agent 真实轨迹。使用前核对许可证和版本，单独呈现结果，不与自建或自采数据混成一个总分。

## 7. 成熟工程接入样例

真实落地时建议把 Agent 侧追踪和主机侧遥测分开采集，再统一映射到 `BehaviorEvent`。

| 来源 | 成熟方案 | 可映射字段 | 本项目接入方式 |
|---|---|---|---|
| LLM/Agent Trace | Langfuse、Phoenix、OpenLLMetry、AgentOps | trace/span 时间、会话、模型调用、工具名、输入输出状态 | 将 span 转为 `source=agent` 的 model/tool/memory/permission 事件 |
| 主机进程与文件 | osquery、Wazuh、Falco | 进程启动、文件读写、网络连接、规则命中 | 将进程树或主机用户作为 `entity_id`，动作归一为 read/write/connect/start |
| 非结构化日志 | Drain/Drain3、LogPai 工具链 | 日志模板、模板参数、时间与主机 | 先做模板解析，再进入统一字段 |
| 策略与规则 | Open Policy Agent、Sigma、ATT&CK 映射 | 策略命中、战术技术、严重等级 | 作为透明规则分或解释标签，不替代模型分 |

本包新增 `configs/otel_span_mapping.example.json`、`configs/osquery_process_mapping.example.json` 和 `configs/wazuh_alert_mapping.example.json`，用于展示真实字段如何进入统一事件模型。这些文件是映射模板，不包含真实日志。

## 8. 推荐补充实验

正式答辩前若时间允许，优先补三组小实验：第一，用 1000 到 5000 条公共或自采脱敏事件跑通 CSV/JSONL 适配；第二，对比 Loglizer 中的 PCA、Isolation Forest、One-Class SVM 与本项目 Transformer；第三，把 AgentDojo 或 InjecAgent 的提示注入任务转写成行为链，只报告“能否接入和解释”，不要虚构高精度指标。
