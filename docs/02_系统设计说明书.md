# AgentGuard 系统设计说明书

## 1. 目标与威胁模型

系统监测被授权环境中的 AI Agent 与承载主机。攻击或失控可能来自提示注入、插件/工具被滥用、凭据访问、持久化、横向移动、批量文件破坏和数据外传。检测器不假定单个事件必然恶意，而判断“在当前实体、时间与前后文中，这一串动作是否偏离正常行为语法”。

不在范围内：阻断攻击、自动删除文件、主动反制、对未授权系统探测。告警默认由安全人员复核。

## 2. 统一事件模型

最低字段：时间、实体、事件类型、动作。对象类型和对象名称补充语义；来源区分 Agent/Host；结果描述成功或失败。标签、场景和风险提示只用于离线评估，模型输入显式排除了 `label`、`scenario`、`risk_hint`，防止答案泄漏。

行为词元由 `source|event_type|action|object_type|result` 组成。未把完整路径、IP、命令行直接加入词元，原因是高基数值会造成词表爆炸并记忆测试实体；对象名称以长度等低风险统计量进入模型，关键原文仍保留在证据中。正式版本可加入经脱敏、分段或哈希的子词特征。

连续特征包括：相邻事件时间间隔的对数缩放、小时正余弦、失败标记、对象名长度、Agent/Host 来源。时间正余弦避免 23:59 和 00:01 被误认为相距很远。

## 3. 序列构建

先按实体分组再按时间排序，以固定长度 24 和步长 8 形成重叠窗口。短序列填充，填充值通过 attention padding mask 排除。窗口过短会丢失“读密钥→外连→上传”的行为链；过长则增加二次方注意力开销并稀释局部异常。24 是演示配置，正式数据应通过 16/32/64 窗口消融选择。

当前演示数据每个实体代表一段会话。对正式主机月日志，应按 `host + user + process tree` 或超时会话键切分，防止把完全无关的全天事件拼成序列。

## 4. 模型结构

事件嵌入与连续特征线性投影相加，再加入可学习位置向量。序列首部添加 `[CLS]`，经过两层、四头、隐藏维 64 的 Transformer 编码器。`[CLS]` 进入二分类头；每个事件隐状态进入下一事件预测头。

总损失：

`L = L_weighted_BCE + λ × L_next_event`

加权 BCE 处理异常样本稀少；下一事件交叉熵迫使网络学习行为顺序，而非只凭某个危险词分类。λ 默认 0.25，过大会让模型只优化常见下一动作，过小则辅助任务不起作用。

选择 Tiny Transformer 而非大语言模型的原因：行为词元不是自然语言；小模型在 CPU 上更稳定，数据不出本地；参数量、时延、内存都更适合现场演示和端侧部署。若正式数据量巨大，可增加层数或使用长序列 Transformer，但应以消融收益为依据。

## 5. 模型分数、规则分数与告警阈值

Transformer 模型分数为 0.8×分类概率 + 0.2×归一化下一事件负对数似然。前者利用弱监督异常增强，后者提供“正常语法偏离”信号。下一事件分数用验证集正常样本中位数至 99 分位区间归一化。

透明规则只在满足严格顺序的行为链上给分，例如“读取敏感对象→外连→上传”或“扫描→远程启动”。实际告警分数取模型分数与规则分数的较大值。两类分数在告警和指标中分别保留，以便判断告警来源，避免把规则收益归功于 Transformer。

阈值不是固定 0.5，而是在验证集候选阈值中选择满足工程目标 FPR≤15% 且检出率最高者，再以 F1 打破并列。15% 是本项目的内部实验约束，不是自主命题赛道的官方硬指标。测试集不得参与阈值选择。

## 6. 可解释性

逐事件贡献 = 0.45×`[CLS]` 对事件的平均注意力 + 0.55×下一事件惊异度。贡献最高的五个事件随告警输出。自然语言模板识别典型链路，例如“不可信内容→提权→读取凭据→外连→上传”。

这样做的理由：只给注意力可能突出“模型看了哪里”却不反映事件有多意外；只给惊异度会忽略全局分类上下文。融合后既保留序列上下文，又提供局部偏离。局限是它仍非因果解释，因此输出原始日志并要求人工复核。

## 7. 数据增强与未知威胁

演示训练集注入多类安全行为链，模拟弱监督/紫队数据增强；测试集同时加入共享高风险词元的困难正常序列。增强样本限定在训练侧，测试按实体隔离，并将横向移动异常模板从训练和验证中留出。当前 Transformer 单模型未检出该留出场景，而透明规则实现覆盖，因此结果只能支持混合系统的工程互补价值，不能声称模型已经具备充分的未知威胁泛化能力。

## 8. 工程架构

- `schema.py`：统一事件与校验；
- `data.py`：词表、特征、会话和 Dataset；
- `model.py`：可返回注意力的 Transformer；
- `engine.py`：训练、阈值、推理、解释、性能评测；
- CLI：数据生成、训练、评估、任意 JSONL 分析；
- 流式分析：每实体窗口与活跃实体数双重上限，LRU 回收前输出尾窗口；
- 本地 Web：零云依赖演示台，提供健康检查、演示结果和上传分析 API；
- `artifacts`：模型、结构化指标、告警证据与图表。

## 9. 安全与隐私设计

默认离线推理；日志仅保存必要字段；展示层应脱敏用户名、路径、IP 与密钥；模型文件和配置计算哈希后归档；告警保留事件原文，形成可审计证据。服务只监听 127.0.0.1，并限制请求体、事件数和字段长度。若要部署到网络仍必须增加身份认证、TLS、速率限制和审计日志。

## 10. 可扩展方向

后续优先做四项：授权真实数据字段适配；跨时间和跨环境评估；LSTM、Transformer 与混合方案消融；多个留一攻击族测试。其次才是蒸馏、INT8 量化、图神经网络或在线漂移检测。扎实证据比堆叠未经验证的名词更重要。
