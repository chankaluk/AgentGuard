# 自主命题赛道 10 分钟答辩稿与问答

## 0:00—1:00 问题

“我们的作品叫 AgentGuard。AI Agent 的风险不只在一句提示词，而在它随后执行的一串动作。读取文件、访问网络、写注册表单独看都可能合法，但‘不可信内容输入—提权—读取密钥—外连—上传’组合起来就是高风险链。我们因此把检测对象从单条日志提升为跨 Agent 与主机的行为序列。”

给非安全背景评委的通俗说法：“AgentGuard 像给 AI Agent 装行车记录仪。它不只看某一个动作，而是看一段行驶轨迹：从用户输入，到工具调用，再到主机文件、进程和网络影响。只有把这些动作连起来，才能看出一次风险链。”

## 1:00—2:30 数据与可信边界

“这是自主命题赛道，没有组委会提供本题数据。我们构建了固定随机种子的增强工程基准，按实体隔离，并加入高风险但合法的顺序扰动样本；横向移动异常模板从训练和验证中留出。所有成绩都明确标为自建基准，只用于证明工程链路，不冒充真实部署效果。”

## 2:30—4:30 方法

讲统一事件字段、长度 24 的重叠窗口、行为词元和时间特征。强调 `label`、`scenario`、`risk_hint` 不进入模型。两层四头 Transformer 同时做异常分类和下一事件预测；独立透明规则只识别严格有序的高风险链。实际告警取模型分数和规则分数的较大值，两者分别保存。

## 4:30—6:00 结果

“400 个测试序列上，Transformer 单模型检出率 65.00%、误报率 15.33%；顺序规则检出率 84.00%、误报率 0；实际混合链路检出率 97.00%、误报率 15.33%、F1 为 0.798。横向移动留出场景由规则补足，说明模型的未知场景泛化仍是限制，也说明分层融合比隐瞒基线更可靠。”

展示 `metrics.json`、分场景图和一条同时含 `model_score`、`rule_score` 的告警。

## 8:30—10:00 创新、限制与总结

“作品不是把日志模型和规则简单拼接，而是围绕 AI Agent 执行链形成三项可验证创新：第一，Agent 与主机双域联合建模，把输入、规划、工具调用和主机影响放进同一行为序列；第二，模型分数与透明安全规则双证据融合，两种来源分别保存、共同决策；第三，面向 AI Agent 安全设计困难负样本和场景留出，专门防止模型只记危险关键词。工程上再用关键事件和原始日志形成证据闭环。当前限制是自建数据规模有限，Transformer 对留出横向移动场景没有泛化成功。下一步将在授权环境采集真实轨迹，进行跨时间、跨环境和多场景留出验证。”

# 高频专家问题

## 1. 97% 是 Transformer 的成绩吗？

不是。97% 是 Transformer 与透明顺序规则联合后的实际混合告警链路；Transformer 单模型为 65%，顺序规则为 84%。系统在指标和告警字段中分别保留三者，避免归因混淆。

Recall 97%、F1 0.798、误报率 15.33% 的关系是：系统偏向安全侧，100 个异常中检出 97 个，但同时把 46 个正常序列报为异常，精确率只有 67.83%，所以 F1 低于 Recall。工程验证阶段优先降低漏报，真实部署必须按角色和误报处置成本重新校准阈值。

## 2. 为什么模型不如规则还要使用 Transformer？

当前自建场景中，规则对已知固定链很强。Transformer 提供连续上下文评分，并对规则没有覆盖的组合保留泛化空间。现有证据支持“互补”，不支持“模型全面优于规则”。真实价值要靠更丰富的授权轨迹和跨环境实验验证。

## 3. 合成数据会不会导致高分？

会，因此主动加入共享危险词元的困难正常样本、实体隔离和场景留出，并展示零学习基线。仍不能消除所有模板偏差，所以报告明确限定为工程基准。

## 4. 如何避免标签泄漏？

模型只使用事件词元和连续特征；标签、场景、风险提示和实体 ID 均不作为特征。测试还检查元数据和切分策略。

## 5. 注意力就是解释吗？

不是因果解释。注意力与下一事件惊异度只用于证据排序，并与规则命中和原始日志交叉核验。

## 6. 如何控制误报？

阈值只在验证集按内部 FPR≤15% 目标选择，测试集不参与调参。真实环境还需按角色或业务分组重新校准。15% 是项目内部约束，不是赛道官方门槛。

## 7. 流式和离线结果会不会不一致？

两条路径共享窗口切分函数，并有长度 5、6、10、24、25、50 的一致性测试。每个实体只保留有限事件窗口，但大规模部署还需增加实体数量上限和过期回收策略。

## 8. checkpoint 安全吗？

加载时使用 `weights_only=True`，校验精确字段集合、版本、张量和配置类型；未知版本直接拒绝。提交包仍需提供哈希，模型文件只从可信来源加载。

## 9. 为什么不调用大模型解释？

核心解释离线、确定、无 API 成本，避免敏感日志外发。大模型可做可选润色，但不能替代结构化证据。

## 10. 最需要改进什么？

第一是真实授权轨迹，第二是多种序列基线和消融，第三是跨时间漂移与告警人工复核。未完成前不写推测数字。

## 11. 和前沿方案、成熟 GitHub 工程相比差在哪里？

AgentDojo、InjecAgent、ToolEmu 等工作更像“攻击与防御评测场”，Langfuse、Phoenix、OpenLLMetry 更像“Agent 调用观测平台”，osquery、Wazuh、Falco 更像“主机遥测和规则来源”。AgentGuard 的位置是在这些数据之后做统一行为序列检测和证据解释。当前项目已经补了接入映射模板和三类补充输入，但还没有真实运行这些外部平台的数据，因此答辩时只能说“已设计对接路线并完成格式接入样例”，不能说“已完成真实平台验证”。

## 12. 三类补充数据怎么讲？

本机正常日志用于证明系统能接真实电脑遥测，并观察误报；隔离可控安全测试日志只生成行为记录，不执行真实攻击，用来展示规则分和证据链；Loghub HDFS 公共样本用于证明系统能接公共系统日志。三类数据都和自建训练基准分开报告，不混成一个总准确率。
