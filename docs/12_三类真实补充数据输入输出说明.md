# 三类补充数据输入输出说明

本文档说明本项目新增的三类补充数据：本机正常行为日志、隔离环境中的可控安全测试日志、公共安全数据样本。它们用于增强“真实格式接入”和“答辩可信度”，不替代 `data/demo` 的可复现实验指标。

## 1. 本机正常行为日志

生成命令：

```powershell
python scripts/collect_local_normal.py --salt "只在本地保存的随机盐"
```

默认输入来源是当前电脑的一次进程和网络连接快照。脚本不会记录命令行、用户名、主机名、远端 IP、Cookie、密钥或完整路径；实体 ID 使用盐哈希脱敏。

默认输出：

- 输入文件：`data/local/normal_from_host.jsonl`
- 摘要文件：`artifacts/local_normal_summary.json`
- 标签策略：全部为 `label=0`
- 适用用途：验证真实本机遥测能转成统一事件格式，观察模型在正常轨迹上的误报情况
- 不适用用途：不能证明攻击检出率，因为它没有真实攻击标签

示例事件：

```json
{"timestamp":"2026-07-22T02:00:00Z","entity_id":"local-xxxx","source":"host","event_type":"process","action":"observed","object_type":"process","object_name":"python.exe","result":"success","label":0,"scenario":"local_normal_snapshot"}
```

## 2. 隔离环境可控安全测试日志

生成命令：

```powershell
python scripts/generate_controlled_security_logs.py
```

该脚本只生成日志，不执行漏洞利用、扫描、凭据读取、外连或上传。它包含一个合法管理员流程和一个可控的“提示注入导致外传”模拟流程。

默认输出：

- 输入文件：`data/local/controlled_security_test.jsonl`
- 摘要文件：`artifacts/controlled_security_summary.json`
- 标签策略：正常流程为 `label=0`，模拟攻击链为 `label=1`
- 预期结果：模拟攻击链应命中透明规则中的 `read secret -> network connect -> upload`
- 适用用途：现场展示“规则分为何升高”和“告警证据链如何形成”
- 不适用用途：不能写成真实攻击环境精度

## 3. 公共安全数据样本

数据来源：Loghub BGL_2k 与 HDFS_2k 公共研究日志样本。BGL 样本第一列带公开异常标签：`-` 表示正常，其它值表示异常；HDFS_2k 在本项目中只作为无标签格式验证样本。

下载示例：

```powershell
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/logpai/loghub/master/BGL/BGL_2k.log" -OutFile data/public/BGL_2k.log
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/logpai/loghub/master/HDFS/HDFS_2k.log" -OutFile data/public/HDFS_2k.log
```

转换命令：

```powershell
python scripts/convert_loghub_bgl.py data/public/BGL_2k.log --limit 500
python scripts/convert_loghub_hdfs.py data/public/HDFS_2k.log --limit 200
```

默认输出：

- BGL 输入文件：`data/public/BGL_2k.log`
- BGL 转换输出：`data/public/loghub_bgl_sample.jsonl`
- BGL 摘要文件：`artifacts/public_loghub_bgl_summary.json`
- BGL 标签策略：第一列 `-` 写为 `label=0`，其它公开标签写为 `label=1`
- HDFS 转换输出：`data/public/loghub_hdfs_sample.jsonl`
- HDFS 摘要文件：`artifacts/public_loghub_summary.json`
- HDFS 标签策略：作为无标签格式验证样本，统一写 `label=0`
- 适用用途：证明 AgentGuard 能接入公共系统日志，并能把 BGL 异常片段展开为可追踪行为链
- 不适用用途：公共系统日志不等同于 AI Agent 攻击轨迹，不能和自建 AI Agent 基准混成一个总准确率

## 4. 如何跑检测

三类数据都输出 JSONL，可以直接进入现有分析入口：

```powershell
python scripts/analyze.py data/local/normal_from_host.jsonl --all --output artifacts/local_normal_alerts.jsonl
python scripts/analyze.py data/local/controlled_security_test.jsonl --all --output artifacts/controlled_security_alerts.jsonl
python scripts/analyze.py data/public/loghub_bgl_sample.jsonl --all --output artifacts/public_loghub_bgl_alerts.jsonl
python scripts/analyze.py data/public/loghub_hdfs_sample.jsonl --all --output artifacts/public_loghub_alerts.jsonl
```

若当前电脑没有安装 PyTorch，转换脚本仍可运行，但 `analyze.py` 需要先执行 `setup_env.ps1` 安装模型依赖。

## 5. 页面上传自动解析

启动演示台后访问 `http://127.0.0.1:8080`，点击“上传日志分析”，可选择 `.log`、`.jsonl` 或 `.txt` 文件。当前自动识别三类输入：

- AgentGuard JSONL：每行一个统一事件对象
- Loghub BGL 原始日志：自动识别为 `loghub_bgl`
- Loghub HDFS 原始日志：自动识别为 `loghub_hdfs`

接口输入：

```json
{"filename":"BGL_2k.log","content":"原始日志文本","limit":500}
```

接口输出：

- `summary.parser`：实际使用的解析器，例如 `loghub_bgl`
- `summary.event_count`：解析出的统一事件数量
- `summary.agentguard_alert_count`：AgentGuard 检出的告警窗口数量
- `summary.public_label_event_count`：公共数据原标签中的异常事件数量
- `results`：按风险分排序的告警列表，包含混合分、模型分、规则分、解释、关键证据和完整时间线

上传内容只在本机 `127.0.0.1` 演示服务进程内解析，不会发到外部服务器。

## 6. 答辩时怎么说

可以说：

“我们补了三类数据入口。本机正常日志用于看真实格式和误报；隔离测试日志用于展示可控风险链，不执行真实攻击；Loghub BGL/HDFS 公共样本用于证明系统能接公共日志，其中 BGL 带公开异常标签，可以现场上传并展开告警时间线。三者和自建训练基准分开报告，不混成一个总准确率。”

不要说：

“本机数据证明攻击检测有效”或“公共样本已经证明真实部署 97%”。
