# AgentGuard 评委通俗讲解稿

## 30 秒版

AgentGuard 做的是 AI Agent 的行为安全审计。AI Agent 会读文件、调工具、连网络、写代码，这些动作单独看不一定危险，但连起来可能形成攻击链。我们的系统把 Agent 动作和主机日志按时间排成一条行为序列，用轻量 Transformer 看它是否偏离正常模式，再用透明规则识别明确的高风险顺序。最后不是只给一个分数，而是告诉评委：哪几个事件触发了风险、模型分是多少、规则分是多少、原始日志在哪里。

## 2 分钟版

可以把 AgentGuard 想成“给 AI Agent 装行车记录仪”。普通日志系统看到的是很多零散事件：读了一个文件、开了一个进程、连了一个地址。AgentGuard 关心的是这些事件前后如何组合。

例如，一个 Agent 先读网页内容，然后突然申请更高权限，接着读取凭据文件，再连接一个新外部地址，最后上传压缩包。每一步单独看可能都有业务理由，但串起来就是高风险链路。

实现上，我们先把不同来源的日志统一成几列：时间、实体、来源、事件类型、动作、对象类型、对象名称、结果。然后按同一个 Agent 或同一棵进程树分组，按时间排序，切成长度 24 的窗口。模型输入不是原始敏感文本，而是行为词元和少量连续特征，例如时间间隔、是否失败、对象名长度。

检测有两条证据线。第一条是 Tiny Transformer，它学习正常行为序列，输出模型异常分，并用下一事件预测衡量“这一步有多意外”。第二条是透明顺序规则，比如“读敏感对象，再外连，再上传”。最终告警取两者较高分，同时保留模型分和规则分，避免把规则效果说成模型效果。

当前结果来自自建可复现工程基准，不代表生产环境。测试集中混合系统检出率 97%，但这不是 Transformer 单模型成绩；Transformer 单模型是 65%，规则单独是 84%。这说明系统现在的价值是工程互补和证据闭环，后续还需要接入真实授权轨迹验证泛化。

## 评委最可能问什么

**问：你们到底创新在哪里？**

答：第一，检测对象不是单条日志，而是 Agent 与主机混合行为序列；第二，模型分和规则分分别保存，不混淆归因；第三，数据里加入高风险但合法的困难正常样本，防止模型只记危险关键词。

**问：97% 是模型准确率吗？**

答：不是。97% 是实际混合告警链路，Transformer 单模型是 65%。我们在报告和告警里都分开保存三种分数，这是为了让结果更可信。

**问：合成数据会不会太理想？**

答：会，所以我们明确把它叫“自建可复现工程基准”。它证明系统能跑通、能复现、能解释，但不能代表真实部署。下一步会接 Langfuse/Phoenix 的 Agent trace、osquery/Wazuh 的主机遥测，再做跨时间和跨环境测试。

**问：注意力能解释模型吗？**

答：注意力不是因果解释。我们只把它当作证据排序线索，并结合下一事件惊异度、规则命中和原始日志让人复核。

**问：为什么不用大模型直接判断日志？**

答：日志可能包含敏感信息，本项目默认离线运行；小模型 CPU 可跑，结果稳定，成本低。大模型可以作为后续报告润色或人工辅助，但不能替代结构化证据链。

## 演示时一句话串联

“请看这个实体的行为链：先发生 Agent 侧输入和工具调用，再出现主机侧文件、进程或网络动作。系统把这些动作切成行为窗口，给出模型分、规则分和最终混合分。下面的关键事件来自原始 JSON 日志，所以这个告警不是页面写死的，而是可以复核的证据链。”
